# 四层系统与路由：这次要动哪一层

这是本 skill 的核心路由文件。所有涉及"解读现象／设计介入／写方案／评审"的任务，都先在这里定位，再分流到具体文件。

**一句话原理**：社会工作的方法不是按"流派"分的，首先是按**系统层次**分的。同一个现象在四层里都是真的，但**四层不能同时作为介入点**——选错层次，技术越熟练，浪费越大。

---

## 1. 四层的判据

| | ① 个案与家庭 | ② 小组 | ③ 社区与组织 | ④ 制度与政策 |
|---|---|---|---|---|
| 改变的对象 | 一个人的处境、一个家的互动 | 成员之间的互动本身 | 资源、关系、权力的空间分布 | 规则、资格、预算、权利 |
| 服务的单位 | 个人、夫妻、家庭 | 成员 + 小组整体（两个对象） | 社区、机构、网络 | 人群类别、制度安排 |
| 工作者角色 | 治疗者、支持者、经纪人、教育者 | 促进者、教育者、调解者 | 组织者、规划者、经纪人、倡导者 | 倡导者、政策分析者、议题推动者 |
| 改变的媒介 | 关系与对话 | 同伴互动与小组结构 | 组织、联盟、行动 | 证据、联盟、议程、谈判 |
| 典型产出 | 一个有共识的目标与可执行任务 | 成员间形成新的互动模式 | 一个新的位置、一项被纳入议程的诉求 | 一条被改动的规则或一次资源重新分配 |
| 见效速度 | 快（周—月） | 中（月） | 慢（季—年） | 最慢（年） |
| 可复制性 | 低（个案化） | 中 | 中 | 高 |
| 证据形态 | 个案过程证据、单系统设计 | 前后测、目标达成 | 案例研究、过程追踪 | 准实验、政策评估 |
| 最强处 | 能把"过不下去"变成下一步 | 用互动本身当改变媒介，成本低 | 能改变位置而不只是心态 | 能改变规则本身 |
| 软肋 | 容易把结构问题个人化 | 容易被当成廉价批量方案 | 见效慢、易被紧急个案打断 | 燃眉之急等不起；个体诉求易被总体利益盖过 |

### 1.1 一条快速判据：「如果十个人处在同一位置」

- 如果十个人处在同一位置会出现大致同样的反应 → 主要矛盾在**结构**（③或④），个案工作只能兜底；
- 如果十个人里只有一个如此，且与其生命史、家庭结构、健康状态高度相关 → 主要工作在**个案**（①）；
- 如果问题主要发生在"人跟人之间"（同一处境的人互相影响、互相消耗、或互相支持）→ **小组**（②）；
- 如果问题表现为"资源明明有、但到不了该到的人手上" → **③**（组织与网络），而不是加资源。

这条判据不精确，但它能挡掉 80% 的层次误判。

## 2. 问句 → 层次 的默认映射

| 用户这样说 | 默认层次 | 理由 | 但要提醒 |
|---|---|---|---|
| 「他现在该怎么办」「怎么跟他说」 | ① 个案 | 主语是具体的人 | 若十人同遇，先看结构 |
| 「怎么让他愿意配合」 | ① 个案 | 动机与关系问题 | 先分清"不愿"与"不能" |
| 「该不该报告 / 要不要告诉他家里人」 | ① 个案（伦理） | 伦理与法律责任问题 | 先看所在地法规与机构规程 |
| 「这个组该怎么带」「组里两个人吵起来了」 | ② 小组 | 对象是互动 | 也可能是①（其中一人有危机） |
| 「社区没人参加活动」 | ③ 社区 | 参与结构问题 | 先分清"不需要"与"进不来" |
| 「这个项目怎么设计」「指标完不成」 | ③ 组织 | 组织与项目管理 | 指标问题常是④ |
| 「这条政策对××不公平」 | ④ 制度 | 规则问题 | 需要证据与联盟，不是靠个案故事 |
| 「用社工视角解释××现象」 | 先问 | 解读可以有四层 | 见 §3 |
| 「我想研究××」 | 先问 | 选题必须定层次 | 见 §3 |

**注意**：上表是默认值，不是答案。默认值的用处是让你有一个起点，然后**主动去找反例**——如果找不到反例，才接受这个默认。

## 3. 只问一次的模板

需要定位时，发一条消息，包含三样东西，**不要写成综述**：

```
这件事可以在四层做，做法和代价很不一样：

┌──────────┬────────────────────┬──────────────────┬────────────────┐
│          │ 能改变什么          │ 需要什么条件      │ 软肋            │
├──────────┼────────────────────┼──────────────────┼────────────────┤
│ 个案/家庭 │ 他的处境与下一步     │ 他愿意谈、时间够   │ 结构问题个人化   │
│ 小组      │ 成员之间的互动       │ 能凑齐人、有共同任务│ 易成廉价批量方案 │
│ 社区/组织 │ 资源与关系的位置     │ 有人可动员、机构授权│ 见效慢、易被打断 │
│ 制度/政策 │ 规则本身            │ 证据、联盟、窗口期  │ 燃眉之急等不起   │
└──────────┴────────────────────┴──────────────────┴────────────────┘

你更想动哪一层？（若不确定，说一句"你帮我选"，我按你描述的现象给默认判断并说明理由）

自测题（各答一句即可）：
① 个案：这个人的处境里，最急的一件事是什么？他自己想先动哪一件？
② 小组：有没有一群人有共同的事要做，且彼此能互相影响？
③ 社区：这件事上，谁掌握着让别人进不来的那道门？
④ 制度：这条规则是谁定的、按什么标准定的、能不能被质疑？
```

**为什么要给自测题**：用户常常答不出"哪一层"，但答得出"最急的是什么"。自测题是把模糊的关切翻译成层次的钩子。

## 4. 错配诊断：五种典型症状

| 症状（用户在说的） | 真正的错配 | 表现 | 处理 |
|---|---|---|---|
| 「我跟他谈了很多次，他都答应了，但没变化」 | ① 被用于 ③/④ 的问题 | 每次会谈都有进展，回到环境就归零 | 检查：他面对的约束是不是别人给的（雇主、学校、房东、政策） |
| 「这个社区的人就是素质不行」 | ③ 被降级为 ① | 结构问题被翻译成个人品质 | 换成"位置—机会"语言重述一遍，看是否更合理 |
| 「我们要搞个活动提升居民参与」 | ③ 被降级为"活动" | 参与被当作到场率 | 见 `09-community-practice.md` §4 的参与判据 |
| 「这个指标我们完成了，但服务对象说没用」 | ③ 被 ④ 的考核逻辑改写 | 可计量项挤掉深度工作 | 见 `12-china-and-governance.md` §4.4 |
| 「这是结构问题，我们改变不了」 | ④ 被用来免除 ① 的义务 | 用宏观解释回避当下风险 | **结构解释不解除保护义务**——先做①，再谈④ |

### 4.1 反向错配：把个案问题结构决定论化

这是专业讨论里最容易被表扬、后果却最重的一种错。它的表现形式是一段听起来很成熟的论述：

> "这不是他个人的问题，是结构造成的。我们能做的很有限。"

这段话可能完全正确，但它**回答的不是当下该做什么**。判据：

- 有没有一个具体的人处在具体风险中（虐待、自伤、断药、失学、失去住所）？→ 有，就先做①，④并行推进；
- 有没有一个明天就要发生的损失？→ 有，就先止损；
- 结构批判有没有对应一个**可执行的诉求**（向谁提、提什么、以什么为筹码）？→ 没有，那它不是分析，是情绪。

## 5. 六种介入角色（层次定了之后，还要定角色）

同一个层次里，社工可以扮演不同角色，角色混用是第二种常见错配。

| 角色 | 做什么 | 典型场合 | 越界风险 |
|---|---|---|---|
| **治疗者 / 支持者** | 处理情绪、认知、关系模式 | 个案、小组 | 把资源问题当心理问题处理 |
| **经纪人（broker）** | 连接资源、转介、代办手续 | 个案、社区 | 变成"代办"从而固化依赖 |
| **教育者** | 提供信息与技能 | 小组、社区、学校 | 变成单向灌输 |
| **调解者** | 处理冲突、促成协议 | 家庭、小组、社区 | 以"和气"压掉正当诉求 |
| **组织者 / 规划者** | 动员、建组织、做方案 | 社区、组织 | 替社区做决定 |
| **倡导者** | 为权利与资源发声、施压 | 各层，尤其③④ | 代言（speaking for）替代同行（with） |

**角色自检三问**：

1. 这个角色是**当事人要求的**，还是我判断他需要的？
2. 如果我一夜之间消失，这个角色留下的是**能力**还是**空缺**？
3. 我有没有在同一个关系里同时扮演"评估者"和"帮助者"，且没有告知对方？

第三问最要命：评估权与帮助权握在同一人手上时，当事人很难拒绝帮助——因为拒绝会被记进评估。

## 6. 跨层组合：哪些是合法的

### 6.1 三种合法组合

| 组合 | 结构 | 适用 | 关键纪律 |
|---|---|---|---|
| **① 兜底 + ④ 倡导** | 个案先把人接住，同时把个案转成政策证据 | 政策缺口造成的一批人同时受损 | **不能因为要做④就推迟①**；也不能拿①的成功证明④没必要 |
| **② 作为 ③ 的起点** | 用小组把分散的人聚起来，再转为社区行动 | 社区动员初期、互助网络建设 | 小组一旦转为行动组，领导权要让给成员，否则变成"社工的活动" |
| **③ 证据 → ④ 议程** | 社区评估的发现成为政策建议的依据 | 试点推动、政策建议 | 证据要能被反驳（说清样本与范围），否则一提就被驳 |

### 6.2 两种非法组合

| 组合 | 为什么非法 | 识别 |
|---|---|---|
| **用①的成功替代④的改革** | 个案成功可以被用来论证"现有安排没问题"；被帮的人被当作制度有效的证据 | 汇报里出现"我们成功帮助了 N 人"却没有任何结构层面的诉求 |
| **用④的批判替代①的保护** | 结构解释不能替代当下的安全评估与法定报告义务 | 讨论中没有人问"这个人今晚安全吗" |

### 6.3 跨层时的记录纪律

跨层方案必须写清三件事，否则执行时必然塌回单一层次：

1. **每一层各自的目标与产出**（不要合成一个目标）；
2. **层与层之间的交付物**（个案发现 → 社区评估 → 政策建议，各有各的载体）；
3. **哪一层可以停、哪一层不能停**（通常是①不能停）。

## 7. 层次选择的自测（8 问）

| # | 问题 | 若答"否" |
|---|---|---|
| 1 | 我能用一句话说清这次要改变的具体对象吗（一个人、一组人、一个地方、一条规则） | 还没定位，别急着选方法 |
| 2 | 这个对象有改变的可能吗（有意愿、有权限、有资源） | 换层，或先创造条件 |
| 3 | 我有权限动它吗 | 先做授权工作，别硬上 |
| 4 | 我有时间动它吗 | 选更快的层，或分层推进 |
| 5 | 如果只做这一层，最坏的副作用是什么 | 写进方案的风险栏 |
| 6 | 我漏掉了哪一层的人（谁在这个方案里没有位置） | 补上，否则方案会被他们推翻 |
| 7 | 这个判断能被什么证据推翻 | 说不出，就是信念不是判断 |
| 8 | 一年后回看，我会希望当初动的是这一层吗 | 这是最终检查 |

第 6 问最实用：**每一个跨层方案都有一批"方案里没有位置的人"**——他们通常是方案失败的原因，而不是方案要帮助的对象。

## 8. 常见误读

| 误读 | 纠正 |
|---|---|
| 宏观比微观"高级" | 层次没有高下，只有匹配。一个人今晚没地方睡，④再正确也不解决今晚 |
| 微观等于"不批判" | 个案工作同样可以批判——只要它不把结构责任转成个人责任 |
| 选一层就要放弃其他层 | 可以并行，但必须分层写目标与交付物 |
| 层次可以事后调整 | 层次决定了要收集什么证据；事后调层通常意味着前面的资料白收 |
| 小组是"省人力的个案" | 小组的媒介是成员互动，不是把个案搬到一群人面前轮流做 |
| 社区工作就是搞活动 | 判据是"评估/活动之后，有没有人获得了一个此前没有的位置" |
